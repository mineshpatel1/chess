# Chess

The game the project exists for. A bitboard engine with alpha-beta search and a UCI interface,
pure standard library. See the [main README](../../README.md) for the shared search, the
`GameState` contract and the learned player.

```bash
python3 play.py                     # play it in the terminal
python3 -m games.chess.uci          # the UCI engine on stdin
```

| Module | What is in it |
|---|---|
| `bitboard.py` | 64-bit board representation, precomputed attack and ray tables |
| `board.py` | `ChessBoard`: position, move generation, legality, FEN, draws |
| `evaluation.py` | Material and piece-square evaluation |
| `move.py`, `piece.py`, `square.py` | Value types |
| `uci/` | Mildred's own UCI server, plus an async UCI *client* for driving other engines |
| `run_engine.py` | Playing Mildred against a third-party engine |

## Representation

Positions are twelve 64-bit integers — one per piece type per colour — plus occupancy masks.
Sliding attacks are generated by masking precomputed rays against blockers; knight, king and pawn
moves come from lookup tables built at import time.

Undo is cheap: `_BoardState` snapshots the raw integers rather than copying the board, so
`make_move`/`unmake_move` is the search's hot path rather than its bottleneck.

`PARALLEL_ROOT` is `True` — chess branches widely enough that splitting the root across a process
pool beats starting one.

Chess has no `SOLVED_DEPTH`, and no `ENCODER`: it cannot be searched to the end, and it is not
currently a target for the learned player in `ai/zero/`.

## Using it in a chess GUI

Mildred speaks [UCI](https://en.wikipedia.org/wiki/Universal_Chess_Interface), so it registers as
an engine in Arena, CuteChess, Scid or any other UCI-compatible GUI. Point the GUI at a launcher:

```bash
#!/bin/sh
cd /path/to/chess && exec python3 -m games.chess.uci
```

| Option  | Type | Default | Range | Meaning |
|---------|------|---------|-------|---------|
| `skill` | spin | 3       | 0–5   | Search depth in plies. `0` plays a uniformly random legal move. |

Search time grows steeply with depth. Talking to it directly:

```
$ python3 -m games.chess.uci
uci
id name Mildred
id author Nesh Patel
option name skill type spin default 3 min 0 max 5
uciok
position startpos moves e2e4 e7e5
go
bestmove g1f3
quit
```

## Playing against other engines

`run_engine.py` plays Mildred against a third-party UCI engine using the async client in `uci/`.
It is the project's only external yardstick — everything else here is measured against itself.

The engines are not in the repository. Drop the binaries under the gitignored
`third-party-engines/` and name one with `--engine`, either by key or by path:

| Key | Path | Reputed |
|---|---|---|
| `stockfish` | `stockfish/Mac/stockfish-11-64` | 3495 ELO |
| `saruman` | `saruman/engine/Saruman` | 1457 ELO |
| `feeks` | `feeks/feeks.sh` | 970 ELO |
| `pos` | `pos/pos.sh` | 111 ELO |

```bash
python3 -m games.chess.run_engine                     # one game against Stockfish
python3 -m games.chess.run_engine -e saruman -n 20    # twenty games, alternating colours
python3 -m games.chess.run_engine --depth 5 --skill 3
```

It reports as a match rather than a game, reusing `MatchResult` from `ai/match.py`, because one
game against an engine says almost nothing — the result is dominated by colour and opening, and the
standard error makes that obvious rather than leaving it to be forgotten. Colours alternate each
game for the same reason.

## Benchmarks

Move generation, on a 4-core container with CPython 3.11:

```
perft(4) from the starting position: 197,281 nodes at ~110,000 nodes/sec
```

Perft is verified against the published
[reference results](https://www.chessprogramming.org/Perft_Results):

| Position | Depth | Expected |
|---|---|---|
| Starting position | 4 | 197,281 |
| Kiwipete | 3 | 97,862 |
| Position 3 | 4 | 43,238 |
| Position 4 | 3 | 9,467 |
| Position 5 | 3 | 62,379 |

All five run inside `tests/chess/test_permutations.py`, so move generation is pinned to the
reference counts rather than merely known to have matched them once.

## Tests

```bash
python3 -m unittest tests.chess.test_moves -v               # rules and legality
python3 -m unittest tests.chess.test_undo -v                # full-game replay, forwards and back
python3 -m unittest tests.chess.test_permutations -v        # perft
python3 -m unittest tests.chess.test_conformance -v         # against the shared game contract
python3 -m unittest tests.chess.test_search_equivalence -v  # search scores, position by position
```

`test_search_equivalence.py` is the net for changing the search, which has no oracle but itself. It
scores **every root move** over a reproducible corpus rather than only the move that wins, because
two searches can agree on the best move and disagree about everything else. Widen `CORPUS_SIZE` and
`DEPTHS` there before touching the search, and expect minutes — cost grows as branching^depth.
